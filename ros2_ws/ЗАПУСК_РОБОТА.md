# Запуск робота — пошагово (ручной режим → автономный маршрут)

Инструкция написана под **текущее** состояние кода в этом репозитории:
одометрия и курс — с камеры Orbbec Astra (RTAB‑Map `rgbd_odometry`),
магнитометра и IMU в стеке больше нет. Разделы README пакета
`robot_navigation` про `mag_calibrator`, `heading_check`, `declination_deg`
и `i2c_check` устарели — этих утилит в сборке нет, выполнять их не нужно.

Все пути ниже даны для случая, когда репозиторий склонирован в
`~/Ros2_ws_orbbec` (рабочее пространство ROS — `~/Ros2_ws_orbbec/ros2_ws`).
Если у вас другой путь — подставьте свой. Проверить:

```bash
ls ~/Ros2_ws_orbbec/ros2_ws/src
# должны быть: astra_odometry cmd_switcher elrs_receiver kolesa_control
#              project_start relay_reliable robot_navigation ...
```

## 0. Как это устроено — за две минуты

```
пульт ELRS ──> /cmd_vel/manual ─┐
                                ├─> cmd_switcher ──> /cmd_vel ──> kolesa_control ──> VESC
Nav2 ─────────> /cmd_vel/auto ──┘   (приоритет: manual > app_manual > home > auto)

камера Astra ─> rgbd_odometry ─> /odom ─┬─> ekf_filter_node_odom ─> TF odom->base_link
GPS ──────────> /gps/fix ───────────────┴─> navsat_transform + ekf_filter_node_map ─> TF map->odom
лидар ────────> /scan ─> relay_reliable ─> /scan_reliable ─> костмапы Nav2
```

Три launch‑слоя, каждый можно запускать отдельно:

| Слой | Команда | Что поднимает |
|---|---|---|
| Железо | `ros2 launch project_start start.launch.py` | пульт, GPS, моторы, камера + VO, лидар (через 10 с), мультиплексор, TF из URDF |
| Локализация | `ros2 launch robot_navigation localization.launch.py` | два EKF + navsat_transform |
| Навигация | `ros2 launch robot_navigation navigation.launch.py` | Nav2 |
| **Всё сразу** | `ros2 launch robot_navigation bringup.launch.py` | 0 с железо → 8 с локализация → 15 с Nav2 → 20 с командир маршрута |

### Режимы управления

Тумблер на **канале 9 пульта (индекс 8)**, трёхпозиционный:

| Положение тумблера | `/control_mode` | Поведение |
|---|---|---|
| 1 — нижнее  | `1` MANUAL      | стики управляют роботом |
| 2 — среднее | `0` AUTO        | `gps_waypoint_commander` отдаёт маршрут в Nav2, робот едет по точкам |
| 3 — верхнее | `3` RETURN_HOME | ничего не публикует — робот стоит |

### ⚠️ Безопасность — прочитать обязательно

1. **В режиме AUTO стики НЕ действуют.** Узел `elrs_receiver` публикует
   `/cmd_vel/manual` только в MANUAL. Поэтому **аварийная остановка —
   перевести тумблер в положение 1 (MANUAL)**: командир маршрута
   отменяет цель в Nav2, мультиплексор тут же переключается на пульт.
   Обратная сторона той же медали: пока тумблер в положении 1 и
   передатчик включён, пульт шлёт команды (нули при отпущенных стиках)
   20 раз в секунду и **перебивает Nav2** — поэтому автопилот может вести
   робота только в положениях 2 (AUTO) и 3 (RETURN_HOME), либо при
   выключенном передатчике.
2. **Потеря связи с пультом в AUTO не останавливает робота** — режим
   «запоминается», Nav2 продолжает вести. Настройте failsafe приёмника
   ELRS в режим *Set Position* и задайте для канала 9 нижнее значение:
   тогда пропажа связи = переход в MANUAL = стоп. И держите под рукой
   физический выключатель питания моторов.
3. **Перед включением питания тумблер должен стоять в положении 1.**
   Узел пульта всегда стартует в MANUAL и переключает режим только когда
   **видит движение** тумблера (порог 0.15 от полного хода + защита от
   дребезга ~0.4 с). Если тумблер при старте уже стоял в положении 2,
   робот в AUTO не перейдёт — чтобы поехать, щёлкните 2 → 1, подождите
   секунду, → 2. Если переключение не сработало с первого раза (щёлкнули
   слишком быстро) — просто повторите с паузой.
4. Если тумблер **двухпозиционный**, среднего положения (AUTO) у него
   нет: либо настройте микшер в передатчике так, чтобы одно из положений
   давало середину канала, либо запускайте маршрут сервисом (см. этап E).
   Проверка — `ros2 topic echo /control_mode`: в нужном положении должно
   печататься `data: 0`.
5. Визуальная одометрия работает **только при свете и при наличии
   текстуры/объектов в кадре** (дальность depth у Astra 0.6–8 м). В
   сумерках, ночью, перед голой стеной или в чистом поле без объектов
   в 8 м `/odom` пропадёт — и вместе с ним локализация. Проверяйте
   `/odom` перед каждым выездом (`ros2 run astra_odometry odom_monitor`).

### 1.3 Библиотеки лидара и камеры (лежат в этом же репозитории)

Драйвер `ydlidar_ros2_driver` не соберётся без YDLidar‑SDK, драйвер
`astra_camera` — без libuvc. Обе библиотеки ставятся в систему один раз:

```bash
# YDLidar-SDK
cd ~/Ros2_ws_orbbec/YDLidar-SDK && mkdir -p build && cd build
cmake .. && make -j2 && sudo make install

# libuvc
cd ~/Ros2_ws_orbbec/libuvc && mkdir -p build && cd build
cmake .. && make -j2 && sudo make install && sudo ldconfig
```

Проверка: `ls /usr/local/lib/cmake/ | grep -i ydlidar` и
`pkg-config --modversion libuvc` — оба должны что‑то вывести. Если
`pkg-config` не находит libuvc, добавьте путь:
`export PKG_CONFIG_PATH=/usr/local/lib/pkgconfig:$PKG_CONFIG_PATH`
(и в `~/.bashrc`, чтобы это пережило перезагрузку). Для JPEG‑потока
камеры libuvc желательно собирать при установленном `libjpeg-dev`.

### 1.4 Порты, права, udev

```bash
sudo usermod -aG dialout,video $USER      # затем перелогиниться!

# UART для пульта и двух VESC (Raspberry Pi 4, /boot/firmware/config.txt):
#   dtoverlay=uart2   -> /dev/ttyAMA2  пульт ELRS
#   dtoverlay=uart4   -> /dev/ttyAMA4  левый VESC
#   dtoverlay=uart5   -> /dev/ttyAMA5  правый VESC
ls -l /dev/ttyAMA2 /dev/ttyAMA4 /dev/ttyAMA5

# udev-правила камеры Orbbec
sudo bash ~/Ros2_ws_orbbec/ros2_ws/src/ros2_astra_camera/astra_camera/scripts/install.sh

# стабильные имена лидара и GPS (VID:PID смотрите в lsusb)
sudo tee /etc/udev/rules.d/99-robot-usb.rules >/dev/null <<'EOF'
SUBSYSTEM=="tty", ATTRS{idVendor}=="10c4", ATTRS{idProduct}=="ea60", SYMLINK+="lidar"
SUBSYSTEM=="tty", ATTRS{idVendor}=="067b", ATTRS{idProduct}=="2303", SYMLINK+="gps"
EOF
sudo udevadm control --reload-rules && sudo udevadm trigger
ls -l /dev/lidar /dev/gps
lsusb | grep -i orbbec        # камера видна по USB
```

Если `/dev/lidar` / `/dev/gps` не создались — `start.launch.py` сам
подставит `/dev/ttyUSB0` для лидара и `/dev/ttyUSB1` для GPS и напечатает
в лог, какой порт выбран. Но после перезагрузки номера могут поменяться
местами, поэтому udev‑правила лучше настроить.

> Если у лидара и GPS одинаковый USB‑UART чип (оба CP210x или оба
> PL2303), правило по VID:PID не различит их. Тогда привязывайтесь к
> физическому разъёму: `ls -l /dev/serial/by-path/` и указывайте эти
> пути через `KERNELS=="1-1.2"` в правиле, либо просто всегда втыкайте
> устройства в одни и те же порты.

Быстрая проверка, что GPS вообще шлёт NMEA на 115200:

```bash
stty -F /dev/gps 115200 raw && timeout 3 cat /dev/gps
# ожидаются строки вида $GNGGA,... / $GNRMC,...
```

### 1.6 Сборка

Скрипты в репозитории лежат без бита исполнения, поэтому запускайте через `bash`.
Собирайте в **новом** терминале, где выполнен только `source /opt/ros/jazzy/setup.bash`:

```bash
cd ~/Ros2_ws_orbbec/ros2_ws
MAKEFLAGS="-j2" bash rebuild.sh        # -j2, чтобы Pi 4 не ушёл в своп на C++ пакетах
source install/setup.bash
```

Ждать 5–15 минут (дольше всего собираются `astra_camera` и `ydlidar_ros2_driver`).
В конце должно быть `Summary: N packages finished` **без** слова `failed`.
Предупреждения `unused parameter` из драйвера лидара — не ошибка.

Если сборка обрывается с `c++: fatal error: Killed signal` — Pi не хватило
памяти на параллельную компиляцию. Соберите последовательно:

```bash
cd ~/Ros2_ws_orbbec/ros2_ws
rm -rf build install log
MAKEFLAGS="-j1" colcon build --executor sequential
source install/setup.bash
```

Чтобы не набирать `source` в каждом терминале:

```bash
echo "source ~/Ros2_ws_orbbec/ros2_ws/install/setup.bash" >> ~/.bashrc
```

## Этап A. Слой железа и ручной режим (робот на подставке)

**Терминал 1:**

```bash
ros2 launch project_start start.launch.py
```

Смотрите лог первые 15 секунд. Должны появиться строки:

- `Connected to ELRS receiver on /dev/ttyAMA2` — пульт открыт.
  Если `Failed to open serial port` — нет оверлея uart2 или прав.
- `КОНФИГУРАЦИЯ ПРИВОДА (DUTY CYCLE)` от `kolesa_control` без ошибок открытия портов.
- `Запуск лидара на порту /dev/...` (через 10 с) и далее без `cannot bind to the specified serial port`.
- От `camera`: открытие устройства без `No device connected`.
- От `rgbd_odometry`: после появления картинки — `Odom: quality=..., std dev=...` (значит VO считает).

**Терминал 2 — проверки по порядку:**

```bash
ros2 node list
# ожидаются: /elrs_receiver /kolesa_control /nmea_navsat_driver /cmd_switcher
#            /relay_reliable /robot_state_publisher /ydlidar_ros2_driver_node
#            /camera/camera /rgbd_odometry

ros2 topic hz /scan                     # ~10 Гц
ros2 topic hz /camera/color/image_raw   # ~30 Гц
ros2 topic hz /camera/depth/image_raw   # ~30 Гц
ros2 topic hz /odom                     # 10–20 Гц — визуальная одометрия жива
ros2 topic echo /gps/fix --once         # на улице status: 0 и координаты; в помещении status: -1
ros2 topic echo /kolesa/diagnostics --once   # напряжение батареи, токи обоих VESC
```

**Пульт.** Подвигайте по одной ручке и смотрите, какой индекс меняется:

```bash
ros2 topic echo /rc_channels --once
ros2 topic echo /cmd_vel/manual         # стик газа -> linear.x, стик руля -> angular.z
ros2 topic echo /cmd_vel                # то же самое должно доходить до моторов
```

Проверьте на подставке:

| Действие | Ожидание | Если не так |
|---|---|---|
| Газ вперёд | обе гусеницы вперёд | `invert_left` / `invert_right` в `start.launch.py` |
| Руль влево (`angular.z > 0`) | левая медленнее/назад, правая вперёд | порты `left_port`/`right_port` перепутаны или `invert_angular` |
| Стики отпущены | гусеницы стоят | `deadzone` / калибровка каналов |

**Тумблер режимов.** В терминале 2 `ros2 topic echo /control_mode`, затем:

- 1 → 2: в логе `TOGGLE SWITCH: Changing to AUTO + AVOID (Position 2)`, в топике `data: 0`. Стики теперь не действуют — это норма.
- 2 → 1: `Changing to MANUAL (Position 1)`, `data: 1`, стики снова работают.

**Путь автопилота до моторов** (без Nav2). Пока тумблер в положении 1,
пульт шлёт нули 20 раз в секунду и перебивает всё остальное. Переведите
тумблер в положение 3 (RETURN_HOME — пульт молчит) и подайте команду в
канал автопилота:

```bash
ros2 topic pub -r 10 /cmd_vel/auto geometry_msgs/msg/Twist "{linear: {x: 0.2}}"
```

Обе гусеницы должны крутиться **вперёд**. Ctrl+C — стоп (мультиплексор
обнулит через 2 с). Верните тумблер в положение 1.

> На этом этапе командира маршрута нет, поэтому положение 2 тоже было бы
> безопасно. Но привыкайте: на этапах C–E **положение 2 запускает маршрут**,
> а для «замолчать, но не ехать» есть положение 3.

**Визуальная одометрия.** Поверните робота на подставке руками / поводите
рукой перед камерой и убедитесь, что поза меняется:

```bash
ros2 run astra_odometry odom_monitor
```

Если печатается предупреждение о потере трекинга — мало света или нет
объектов в 0.6–8 м перед камерой.

Остановите всё: Ctrl+C в терминале 1, дождитесь завершения.

## Этап B. Локализация без Nav2 (на улице, можно на земле)

Вынесите робота на открытое место. **Терминал 1:**

```bash
ros2 launch robot_navigation bringup.launch.py use_navigation:=false use_commander:=false
```

Подождите ~30 с (локализация стартует на 8‑й секунде, лидар — на 10‑й).
Дождитесь фикса GPS: холодный старт до 2 минут.

**Терминал 2:**

```bash
ros2 run robot_navigation nav_preflight_check --ros-args -p expect_nav2:=false
```

Через 15 с получите чеклист. Нужны `[ OK ]` по датчикам, GPS‑фиксу,
`map -> odom`, `odom -> base_link`, `/odometry/gps`, `/odometry/global`.
Пункт про Nav2 будет `[ ?? ]` — это ожидаемо.

Если `/odometry/gps молчит` при живом фиксе — `navsat_transform` ещё не
получил `/odometry/global` или прошло меньше 3 с (`delay`); повторите.

**Выравнивание курса.** У визуальной одометрии курс относительный, север ей
неизвестен. Абсолютный курс «подхватывается» из GPS‑трека только в движении.
Поэтому проедьте **пультом по прямой 10–20 м**, глядя на:

```bash
ros2 topic echo /odometry/global --field pose.pose.position
```

`x`/`y` должны расти в одну сторону ровно, без прыжков и разворотов.
Повторите `nav_preflight_check`: строка «Смещение курса VO и EKF» должна
перестать «плыть» между запусками. Это и есть готовность локализации.

Остановите launch (Ctrl+C).

## Этап C. Nav2: пробная цель

> **Сначала — как пульт взаимодействует с Nav2 на этом этапе.**
> Пока тумблер в положении 1 (MANUAL), пульт публикует `/cmd_vel/manual`
> 20 раз в секунду — **даже нули**, когда стики в центре. У этого канала
> высший приоритет в `cmd_switcher`, и он перебивает Nav2. То есть при
> включённом пульте в MANUAL робот по цели Nav2 **не поедет**.
>
> Поэтому на время пробной цели переводите тумблер в **положение 3
> (RETURN_HOME)**: пульт замолкает, командира маршрута на этом этапе нет
> (`use_commander:=false`), и мультиплексор отдаёт моторы Nav2.
>
> **Остановка: тумблер → 1.** Пульт снова начинает слать команды (нули
> при отпущенных стиках) и мгновенно перебивает Nav2; дальше можно
> отъехать стиками. Ctrl+C в окне `send_test_goal` тоже отменяет цель.
> Крайний случай — выключатель питания моторов.
>
> Утилита печатает «движение стика немедленно перехватит управление» —
> для текущего кода это верно только после возврата тумблера в положение 1.

### C1. На подставке (на улице — нужен GPS‑фикс, иначе не будет TF map→base_link)

**Терминал 1:**

```bash
ros2 launch robot_navigation bringup.launch.py use_commander:=false
```

Подождите ~40 с (Nav2 на 15‑й секунде, на Pi 4 активируется ещё 10–20 с).

**Терминал 2:**

```bash
ros2 lifecycle get /bt_navigator        # ожидается: active [3]
ros2 lifecycle get /waypoint_follower   # active [3]
ros2 lifecycle get /controller_server   # active [3]
ros2 run robot_navigation nav_preflight_check     # теперь и Nav2 должен быть [ OK ]
```

Если узлы не `active` через минуту — смотрите лог терминала 1: чаще всего
это `Failed to find a free participant index` (п. 1.5) или ошибки TF
(нет `map -> odom` → этап B не пройден).

Пробная цель 3 м вперёд. Утилита возьмёт положение из TF, покажет цель и
спросит подтверждение:

```bash
ros2 run robot_navigation send_test_goal --ros-args -p dry_run:=true   # только показать
# тумблер -> положение 3, затем:
ros2 run robot_navigation send_test_goal                               # поехать, ответить y
```

Параллельно в третьем окне удобно смотреть `ros2 topic echo /cmd_vel/auto`
и `ros2 topic echo /cmd_vel` (второй — то, что реально уходит на моторы;
если там нули при ненулевом `/cmd_vel/auto` — пульт всё ещё перебивает,
проверьте положение тумблера).

Гусеницы должны крутиться **вперёд**. На подставке робот «не доедет»
(камера и GPS не видят движения) — через 20–30 с нажмите Ctrl+C, цель
отменится. Тумблер → 1.

### C2. На земле, на открытой площадке

Оператор рядом, пульт в руках, тумблер в положении 1. Запустите утилиту,
подтвердите цель, **затем** переведите тумблер в положение 3:

```bash
ros2 run robot_navigation send_test_goal --ros-args -p distance:=5.0
```

Робот должен проехать ~5 м вперёд и остановиться. Тумблер → 1. Затем
проверка поворота (та же последовательность):

```bash
ros2 run robot_navigation send_test_goal --ros-args -p bearing_deg:=90.0
```

Робот обязан развернуться **влево** и проехать. Если вправо — курс
инвертирован: смотрите знак `angular.z` в `/cmd_vel` при повороте пультом
влево (должен быть `> 0`) и `invert_angular` в `start.launch.py`.

Остановите launch (Ctrl+C).

## Этап D. Маршрут (файл с GPS‑точками)

Формат файла (понимаются и `lat`/`lon`, и `latitude`/`longitude`):

```yaml
waypoints:
  - latitude: 56.299145
    longitude: 43.923061
  - latitude: 56.299500
    longitude: 43.923800
```

Правила: соседние точки на **3–50 м** друг от друга (лучше 5–20 м),
точка на каждом повороте, первая точка не дальше ~50 м от места старта.
Командир при загрузке печатает длину каждого участка и предупреждает
о нарушениях.

### Вариант 1 (рекомендуется): записать маршрут приёмником робота

При работающем `bringup` (годится любой вариант с локализацией, например
из этапа B) — **терминал 2:**

```bash
ros2 run robot_navigation gps_waypoint_logger --ros-args -p output_file:=$HOME/route.yaml
```

Катайте робота пультом, в каждой нужной точке останавливайтесь и в
**третьем терминале** вызывайте:

```bash
ros2 service call /gps_waypoint_logger/log_waypoint std_srvs/srv/Trigger
# ошиблись:
ros2 service call /gps_waypoint_logger/undo_waypoint std_srvs/srv/Trigger
```

Файл сохраняется после каждой точки. Для первого заезда достаточно
**двух точек метрах в десяти друг от друга**.

### Вариант 2: старый файл `project_start/config/waypoints.yaml`

В нём 18 точек, формат поддерживается, но участок **6→7 = 63.9 м** — больше
лимита. Скопируйте файл в `~/route.yaml` и добавьте между 6‑й и 7‑й точкой
промежуточную (реальную точку на дороге между ними, снятую логгером или
с карты), иначе на этом участке Nav2 вернёт `204 GOAL_OUTSIDE_MAP`.

## Этап E. Автономный заезд

**Терминал 1:**

```bash
ros2 launch robot_navigation bringup.launch.py waypoints_file:=$HOME/route.yaml
```

Путь к файлу — **абсолютный**. Без этого аргумента берётся пустой файл из
пакета и командир напишет «Маршрут пуст».

Подождите ~40 с. В логе командира (стартует на 20‑й секунде):

```
Загружено точек маршрута: N. Повторов маршрута: 0. Ожидание команды на старт ...
  участок 1→2: 11.6 м
  ...
```

**Терминал 2:**

```bash
ros2 run robot_navigation nav_preflight_check     # всё [ OK ]
```

Затем **пультом проехать 10–20 м по прямой** (желательно в сторону первой
точки) — выравнивание абсолютного курса, см. этап B. Остановитесь, стики
в центр.

**Старт маршрута** — один из двух способов:

- тумблер **1 → 2** (AUTO) — основной способ; или
- `ros2 service call /gps_waypoint_commander/start_route std_srvs/srv/Trigger`
  — работает **только если пульт молчит** (передатчик выключен или тумблер
  в положении 3). При тумблере в положении 1 пульт шлёт нули в
  `/cmd_vel/manual`, они перебивают Nav2, и робот не сдвинется.

В логе командира по порядку:

```
Пульт переведён в AUTO — стартуем.
До первой точки маршрута: 12.3 м
Ожидание экшен-сервера /follow_gps_waypoints...
Маршрут отправлен в Nav2: N точек
Nav2 принял маршрут, робот поехал.
Едем к точке 2/N
...
Маршрут пройден полностью.
```

В каждой точке робот делает паузу 2 с (`waypoint_pause_duration`), допуск
прибытия 1.5 м (`xy_goal_tolerance`), курс в точке не важен.

**Остановка:**

- тумблер **→ 1 (MANUAL)** — командир пишет «Пульт переведён в режим 1 — маршрут отменён», управление у стиков;
- или `ros2 service call /gps_waypoint_commander/cancel_route std_srvs/srv/Trigger`;
- в крайнем случае — выключатель моторов.

Повторить маршрут несколько раз: `number_of_loops:=2` в аргументах `bringup`.

### Первый заезд — рекомендации

- Пустая площадка, две точки, оператор идёт рядом с пультом в руке.
- Снизьте скорость: в `src/robot_navigation/config/nav2_params.yaml`
  `desired_linear_vel: 0.6` → `0.3` и `velocity_smoother.max_velocity: [0.3, 0.0, 0.8]`,
  затем `cd ~/Ros2_ws_orbbec/ros2_ws && colcon build --packages-select robot_navigation`
  (обычная сборка копирует файлы, поэтому пересборка обязательна) и
  `source install/setup.bash`.
- Следите за `ros2 run astra_odometry odom_monitor` во втором окне: потеря
  трекинга камеры = потеря локализации.

| Симптом на заезде | Куда смотреть |
|---|---|
| Уходит вбок от прямой между точками | курс не выровнялся — проедьте дольше по прямой перед AUTO; проверьте `/odometry/global` |
| Кружит у точки, не может «доехать» | `xy_goal_tolerance` меньше точности GNSS — увеличьте |
| Крутится на месте, потом едет | RotationShim доворачивает нос — норма при большом отклонении курса |
| Стоит, в логе `NO_VALID_PATH` (208) / `GOAL_OUTSIDE_MAP` (204) | препятствие на костмапе или точка дальше 50 м |
| Дёргается, `Control loop missed its desired rate` | не хватает CPU: снизьте `controller_frequency`, fps камеры |
| `/odom` пропал, EKF ругается на timeout | камера потеряла трекинг: свет, текстура, дальность |

## Если что‑то не поднялось — быстрая диагностика

```bash
ros2 topic hz /gps/fix /odom /scan_reliable        # живы ли датчики
ros2 topic echo /gps/filtered --once               # отфильтрованная позиция WGS84
ros2 run tf2_tools view_frames                     # frames.pdf: map -> odom -> base_link -> camera_link/laser_frame/gps_link
ros2 lifecycle get /bt_navigator                   # active [3]
ros2 service list | grep fromLL                    # сервис navsat_transform для GPS-точек
pgrep -a -f 'ros2 launch'                          # зависшие процессы
```

| Ошибка | Причина / решение |
|---|---|
| `Failed to find a free participant index for domain 0` | п. 1.5 (`bash setup_dds.sh`), закрыть старые процессы |
| `PackageNotFoundError: No package metadata was found` | смешаны режимы сборки → `bash rebuild.sh` |
| `package 'X' not found` при launch | не выполнен `source install/setup.bash` в этом терминале |
| `cannot bind to the specified serial port` (лидар) | порт занят/не тот; `ls -l /dev/lidar /dev/ttyUSB*` |
| `Failed to open serial port` (пульт) | нет `/dev/ttyAMA2` (оверлей uart2) или нет группы dialout |
| Nav2 `ОТКЛОНИЛ маршрут` | нет сервиса `/fromLL`: navsat_transform без фикса |
| Робот «прыгает» между двумя позициями | кто‑то ещё публикует `odom -> base_link`; `publish_tf` у rgbd_odometry должен быть false |
| `Старт отменён: приёмник ещё не поймал спутники` | подождать фикс, `ros2 topic echo /gps/fix` |

Подробнее — `src/robot_navigation/README.md`, раздел «Диагностика»
(кроме пунктов про I2C/магнитометр — они к текущему стеку не относятся).
